3. DESIGN — the bare universe (and why)
=========================================================================
Raw code stores potions in RAW-typed slots (measured: BambooSpikesBlockTile
`public Potion potion` field; tryApplyPotion(Potion); if_acmpne identity compares).
A Holder-shaped bridge return would VerifyError at those slots — the bare universe
is the only coherent one: bridges return/accept BARE registered Potion instances,
site descs stay the RAW shapes (only the owner moves), and the EXISTING
repairHolderUnwraps field pass already unwraps the Holder-kind constants to bare
at exactly those consumers (measured in the 5.16-translated jars BEFORE this
phase: getstatic WATER:Holder; value(); checkcast Potion; if_acmpne — the pass's
ASTORE/ACMP/bare-consumer branches). Bare-vs-bare is the one identity universe.

"no potion" = PotionCompat.EMPTY.value() — the bare sentinel INSIDE the existing
synthetic Holder (same instance the EMPTY field sites compare against after
unwrap) — so getPotion(...)==EMPTY stays TRUE for potion-less stacks (1.20.1
semantics restored; a fresh synthetic Potion is never in the registry, never
equal to a real potion).

Verifier mystery CLOSED (5.12 boot-past explained): raw getDefaultInstance does
`getstatic Potions.POISON; invokestatic makeSpikeItem(Potion)` — with the 5.12
desc swap this LOOKS like a Holder-into-Potion-param verify error at class load,
yet 5.12-5.16 booted. Reason: the field-unwrap pass inserts value()+checkcast
before the bare-arg consumer (verified in the translated jar:
`getstatic POISON:Holder; invokeinterface value; checkcast Potion;
invokestatic makeSpikeItem:(Potion;)`). The pass covers field producers; METHOD
producers (my bridges) don't need it — the bridge desc is already the raw shape.
