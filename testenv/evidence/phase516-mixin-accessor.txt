getInvalidClassError has three message variants; which one fires is diagnostic:
  #1 class IS in config.getClasses(): "Illegal classload request for %s. Mixin is

     variant: "... the mixin has not been applied"
  #3 neither: "%s is in a defined mixin package %s* owned by %s and cannot be
     referenced directly"   <-- THE 5.15 WALL (live log, 4 occurrences)

  accessors apply" (the 5.15 systematic candidate) cannot release direct loads.
- The 5.14 empirical asymmetry (ml's DispenserBlockAccessor "loaded fine, NSME") is

3. THE MECHANISM (fallback chosen, for the decoded reason above)
=========================================================================
Accessor call-site rewrite over the EXISTING memberretarget |static kind:

  rules/memberretargets.txt (+1 rule):
  net/mehvahdjukaar/supplementaries/mixins/forge/MobBucketItemAccessor
    |()Lnet/minecraft/world/entity/EntityType;|invokeGetFishType
    -> @SHIM@/MobBucketItemBridge
    |(Lnet/minecraft/world/item/MobBucketItem;)Lnet/minecraft/world/entity/EntityType;|static

  NEW rewriter behavior (rewriter/Rewriter.java, the |static branch): when a
  static retarget fires, an ADJACENT preceding `checkcast` whose desc is the
  rule's KEY owner is DROPPED (counter: "mixin phase-5.16: accessor checkcasts
  dropped=N" in the translate summary). Adjacent-only => no StackMapTable frame
  can fall between; checkcast is 1->1 so the drop is stack- and frame-neutral.
  Without the drop the cast would still classload the accessor and trip the guard.

  NEW shim (shims/src/com/modbridge/shim/MobBucketItemBridge.java, built into
  rules/shims/, injected per-mod to com/modbridge/shim/supplementaries/):
  static EntityType<?> invokeGetFishType(MobBucketItem) — reflective
  setAccessible read of MobBucketItem.type (the proven RegistryCompat idiom).
  21.1 field `private final EntityType<?> type` erases to EXACTLY the accessor
  method's return desc, so the retarget is stack-identical.

  LESSON (boot 1 of this phase, live): the |static retarget keeps the call
  site's METHOD NAME (owner+desc swap only) — the first boot NSME'd
  ("net...MobBucketItemBridge.getFishType") because the bridge method was named
  getFishType; renamed to invokeGetFishType (the accessor's own method name),
  rebuilt, boot 2 crossed the wall. The shim-method-name-must-equal-the-site-name
  rule is now documented in the shim javadoc.
