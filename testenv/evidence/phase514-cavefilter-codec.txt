## WHAT FELL (12 boots, each measured-then-fixed)

1. THE OVERRIDE-RETURN REWRITE (rules/overridereturns.txt, 16 family entries; the
   mechanism the slice was scoped for): the override's desc -> ()MapCodec, its
   generic signature follows, and every ARETURN is fronted by
   MapCodec.assumeMapUnsafe. Stack-neutral; fail-fast on branch frames/statics;
   transitive implements via the jar-local hierarchy (platform supers never
   walked). Offline proof on the real jars:
     CaveFilter$Type.codec: descriptor ()Lcom/mojang/serialization/MapCodec;
       0: getstatic CaveFilter.CODEC
       3: invokestatic MapCodec.assumeMapUnsafe
       6: areturn
     (WaySignStructure$Type identical; counters: ml override returns=1,
      supp override returns=1.)
   SEMANTIC PROOF (gate, real DFU 8 + real PlacementModifierType interface):
   the rewritten bytes, defined in the test JVM, return a MapCodec; decode of
   {"type":"moonlight:cave_filter","n":42} (type key present, same-level
   fields) yields the payload; encode emits same-level entries with no
   "value" key. RESULT: the CaveFilter AbstractMethodError is GONE (0 hits in
   every boot after the rules landed) and the worldgen parse proceeds.

2. from_mod conditioned-data strip (agent wiring + Rewriter resource pass).
   Boot 1 wall after (1): vanilla 21.1 loads moonlight's CUSTOM registries
   (moonlight:soft_fluids, moonlight:map_markers) through the strict
   RegistryDataLoader; 1.20.1 moonlight loaded them through its own from_mod-
   aware lenient loader — supp ships 80 conditioned compat files naming ~30
   mods absent from the testbed => "Registry loading errors" => "Failed to load
   datapacks, can't proceed". Fix: the agent collects the instance's present
   mod ids ("[ModBridge] present mod ids for from_mod data conditioning:
   [minecraft, c, supplementaries, moonlight]"; FIRST modId per jar — the
   [[dependencies]] modId lines poisoned the first attempt, boot 3), and the
   rewriter drops data .json files with (1) top-level from_mod naming an absent
   mod, (2) any absent-mod id reference inside data/<ns>/moonlight/** (supp's
   own teas: black_tea/coffee/... carry NO from_mod but their "id" names
   farmersrespite items; sap/builders_tea/sugar_water reference
   thermal/autumnity/create/the_bumblezone). Drops measured: 12 (ml) + 105 (supp).

3. BuiltInLootTables field drift (NEW PASS rules/fieldunwraps.txt): ALL 113
   fields moved ResourceLocation -> ResourceKey<LootTable>, names survive; 12
   measured sites (supp reg/LootTablesInjects x11 incl. SHIPWRECK_TREASURE —
   the live wall "does not have member field 'ResourceLocation
   SHIPWRECK_TREASURE'" NSFE, fatal through the loot-inject event — plus
   MineshaftElevatorPiece, UrnBlock). THE TRANSFORM IS TWO-PART (boot 5 proved
   the single-part version a VerifyError: the JVM verifier types the getstatic's
   pushed value from the CONSTANT-POOL descriptor, not the resolved field): the
   CP desc -> ResourceKey AND ResourceKey.location() inserted immediately after
   (stack- and frame-neutral). Counters: supp field unwraps=14. LINK-TIME
   PROOF: the gate defines the rewritten class in-JVM and runs it (the exact
   VerifyError regression pinned).

5. CraftingHelper shim family completion (phase 5.7's shim was short):
   processConditions(JsonObject,String,ICondition.IContext) — moonlight's
   resource-conditions mixin (applyResourceConditions, injected into vanilla
   SimplePreparableReloadListener) calls it at datapack reload (boot 7 NSME);
   1.20.1 semantics (missing key = load; all conditions must test). PLUS the

6. MapRegistry.dispatch CCE (NEW PASS fixMapRegistryDispatch, PINNED single
   site): boot 9 wall "MapCodec$MapCodecCodec cannot be cast to MapCodec" at the
   villager-trades reload — DFU 8 KEPT Codec.dispatch's erased descriptor (the
   MapCodec bound is generic-only, javap'd) but KeyDispatchCodec.decode casts
   the produced value codec to MapCodec, and the registered RecordCodecBuilder
   products ARE MapCodecCodec wrappers on DFU 8. Fix (shape-neutral outward):
   the value lambda (checkcast Codec; areturn) becomes
   checkcast Codec; assumeMapUnsafe; areturn with the lambda desc + indy
   instantiated type following to (Object)MapCodec (the raw samMethodType stays
   Function.apply(Object)Object — javac emits the erasure there; boot 10 caught
   the first draft matching the wrong arg); Codec.dispatch -> dispatchMap
   keeping the INVOKESPECIAL(itf) same-class default super-call shape, and the
   result wraps through MapCodec.codec() (INVOKEVIRTUAL — MapCodec is a class;
   an INVOKEINTERFACE there is an IncompatibleClassChangeError, boot 10) so
   dispatch's declared Codec return and ModItemListing.CODEC stay byte-identical
   to 1.20.1.

7. Accessor-rename scoping (phase-4 regression, second live hit; boots 11-12):
